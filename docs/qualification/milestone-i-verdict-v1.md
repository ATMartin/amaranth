## Should fix
1. `.multiple` runs compare by ordered list, not by set. `Presentation/TranscriptRows.swift:127` uses `last.assignment == row.assignment`, and `SpeakerAssignment.multiple([a,b]) != .multiple([b,a])`. The brief, the doc comment (TranscriptRows.swift:114-116, "same set of speakers") and results doc say "same set". `MeetingReconciler.swift:81` builds the list from a score-ranked filter, so two overlap rows with the same speakers can come out in different order and then each shows the name again. The test `overlappingRowsGroupOnlyWithTheSameSpeakers` (Tests/UI/TranscriptRunsTests.swift:~35) asserts the opposite of the documented semantics (`[lee,dana]` does not group with `[dana,lee]`). Either compare `Set(speakerIDs)` and fix the test, or correct the comments and docs. Impact is cosmetic (extra name repeats on overlap rows).
2. `SpeakerMenuTests.columnAndBarProduceTheSameEdits` is close to tautological: both sides call the same `EditComposer` with the same ids, so it cannot detect a wiring difference between column and bar. The equivalence is true by code reading (TranscriptPane.swift: both use `rename(_:)` / `merge(_:into:)` -> `apply`), but the results doc's "shows the column and the bar produce identical edits" is overstated. Reword it, or note that the guarantee comes from the shared functions.
3. Evidence-jump retry loop (TranscriptPane.swift `.onChange(of: library.focusRowID)`): the three passes re-set `selectedRow = id` and `scrollTo` for up to ~240 ms unless `focusRowID` changes. A newer focus is respected (guard on `focusRowID == id`), but a user click or scroll in that window is overridden, and `focusRowID` is not cleared after the jump. Low risk, but the claim "can't fight a user scroll" does not hold for the first quarter second. The Task is also not cancelled when the pane disappears. Acceptable; record it as known, or cancel the task on disappear.
